## 1. Hypothesis

The reachability endpoint is readable on this substrate: the number of iterations a run takes to cross a fixed aggregate `val_loss` level separates individuals more than it separates replicate twins. Formally, at every accepted grid level L (§3–§5): **between-gap(L) > twin-gap(L)** (§4). This is the reachability class the plan substitutes for the order-of-final-states class (plan §1); the gate that reads the outcome is the plan's §3 item 3, not this file.

The alternative — run-to-run scatter moves crossing time as much as individual identity does — is a **fail**, not a surprise, and is the outcome the plan already words: the ranking-class endpoint would be dead on this substrate and road A the honest reading (plan §3 item 3). A fail of this test is a result about the instrument, and it licenses nothing else by itself (§9).

Why this endpoint and not another: the (b) test of the other registration asks for the **order of final states**, and run-to-run scatter destroys an order; USPEX's own statistic asks **how many steps it takes to reach a target fixed outside the run** — the class registered here (plan §1). The target is fixed by §3's rule before any crossing time exists, which is what makes the quantity a reachability and not a ranking.

## 2. The endpoint, precisely

**Endpoint.** For each run r and each registered level L: `cross(r, L)` = the **first checkpoint iteration at which r's aggregate `val_loss` curve value is ≤ L**. This is the whole observable. No interpolation between checkpoints is used anywhere in this test — crossing times are checkpoint iterations, elements of the checkpoint grid of §5, and nothing between two checkpoints exists for this purpose. Stated as a rule because it will be tempting: a crossing time "between checkpoints" is not a number this test can produce.

Definitional note: the curves are not required to be monotone. A curve that dips below L and rises again crosses at the dip — the **first** checkpoint at or below L, once, and that value is `cross(r, L)`. No "stable crossing", no "last crossing", no requirement that the curve stay below L afterwards; those are different quantities and none of them is registered here.

**Field.** The test runs on the **checkpoint curve field** — the 72 aggregate `val_loss` checkpoints per run in **`results/night4/night_report_checkpoints.csv`** — the one file that carries all eight runs (72 data rows, 8 run columns); the glob `results/night*/night_report_checkpoints*.csv` also matches three narrower files of 4 and 6 columns and is **not** the registered substrate — and **not** on the 250,000-hook field (§7). Every value, every gap and every comparison in this document is computed in the curve field.

**One registered reading.** The reading is done once, after this document is reviewed and on the word the plan registers (plan §7 item 1). The grid constants are resolved once at reading time and recorded **before any crossing time is computed** (§3); after that they are frozen. No second computation under other constants is a reading of this registration.

## 3. The threshold grid, as a rule (plan §4(a))

The grid is a self-executing rule, not a list, so that no unpublished number is needed to write it and no choice remains at reading time:

> All levels L = m · step, integer m, with **step = 2.0 loss units** (registered choice — fix in review), lying strictly inside the open interval **(Lmin, L0)**, where
>
> - **Lmin = the maximum over the eight runs of that run's curve minimum = 1161.6192** (run 3′, at iteration 248,412), and
> - **L0 = the minimum over the eight runs and over the control iterations {0, 12} = 1211.5978** (seed 4, at iteration 12),
>
> both computed once at read time from the substrate named in §10.

**Why these two quantities and not the ones v1 used (Revision v2, 2026-09-17 UTC).** v1 set `Lmin` to the *minimum of the eight final values* (1144.6362) and `L0` to *seed 0's iteration-0 value* (1212.5556). Both were the wrong quantity for the job the anchor does, and both were wrong in the direction that makes a guard load-bearing:

- **The lower anchor governs §4's exclusion rule, which fires when a run never crosses a level — and that is decided by a run's *curve minimum*, not by its final value.** The curves are not monotone: seed 0 ends at 1148.8075 but reaches 1141.0463 at iteration 219,612, a difference of 7.8. The binding run is the replicate **3′**, whose curve never goes below **1161.6192** — 17.0 above v1's anchor. Under v1, levels 1146.0—1160.0 — **8 of 34** — were excluded by construction, while §3 asserted the exclusion rule would be nearly empty. The per-run curve minima, for the record: seed 0 1141.0463, 0′ 1156.0002, seed 1 1139.7140, seed 2 1137.8219, seed 3 1150.9345, seed 4 1150.0934, **3′ 1161.6192**, seed 5 1143.1055.
- **The upper anchor has to clear §6's second prong, which tests against iterations 0 *and 12* of all eight runs**, whose minimum is 1211.5978 (seed 4 at iteration 12) — not against seed 0's iteration-0 value alone. Under v1 the top grid level, 1212.0, passed §3 and violated prong 2; it was removed only because §5 happened to drop it on the data, and only at `step = 2.0`. A guard whose emptiness depends on the data and on a registered constant is not a confirmation, it is a filter. The iteration-12 values: 1212.2575, 1212.2574, 1211.7471, 1211.8746, 1211.7933, **1211.5978**, 1211.7932, 1212.0451.

**The resulting registered grid is 1162.0 … 1210.0 inclusive — 25 levels** (two of which are then withdrawn by the caveat in §11, leaving 23). With these anchors §4's exclusion rule and §6's prong 2 are empty **by construction**, and `step` stops being load-bearing. That is recorded as a consequence, not as a merit: the same property that takes `step` out of the criterion also takes away prong 2's ability to fail, which is what makes it a dead guard (§6, v4). Two things bought with one coin, and only one of them was wanted.

Why a rule and not a list: a grid chosen after looking at the curves manufactures a stable threshold by selection (plan §4(a)). The shape is fixed now — multiples of one step in an open interval **both of whose ends are computed mechanically at reading** (v1 published the upper end; v2 replaced it with a computed minimum and this sentence kept v1's language until v3); the constants are resolved once, in the order below, and then frozen:

Why the interval is open at both ends: a level at or above L0 sits in the untrained band that §6's control requires accepted levels to stay below, and a level at or below Lmin is never crossed by **the run whose curve minimum is highest**, so it falls to §4's exclusion rule. With the v2 anchors both guards are empty by construction — §4's exclusion rule and §6's prong 2 should report **zero** levels removed, and a non-zero count would not be a finding about the substrate at all. A zero from either is **not a pass** — it is the arithmetic restating the rule that produced it. **And the non-zero branch is as unreachable as exit 4, so it is marked here rather than left in a form that reads like a live sensor (Ark, 2026-09-18).** Since v2 both anchors are computed from the same eight curves in the same run — `Lmin` is the maximum of the curve minima and every level lies strictly above it — every run therefore crosses every level, at no data whatsoever. A non-zero count could only mean that the anchors and the exclusion rule were computed over different sets of curves, which is **a defect in the code, not a property of the flies**. The wording it replaces ("a finding about the substrate") was v1's, from when the anchors were published constants that could genuinely disagree with the file.

1. Read the eight runs' checkpoint curve files (§10) and the iteration-250,008 curve value of each run.
2. Compute **both anchors** — Lmin from the eight curve minima and L0 from the eight runs × control iterations — and write each down with the run that binds it. Step 3 is impossible without L0, and v2's order named only Lmin.
3. Write down the full list of grid levels; this list, once written, is the grid.
4. Only then compute any crossing time `cross(r, L)`.
5. Apply the exclusion rule (§4), the disqualification rule (§5), the positive control (§6), and only then the acceptance criterion (§4).

## 4. Statistic and acceptance criterion (plan §4(b))

The eight runs are seeds 0–5 plus the two replicates 0′ and 3′; the two replicate pairs are 0/0′ and 3/3′. The six individuals are seeds 0–5, each represented by its **canonical run**: seed i's run, with seeds 0 and 3 represented by their **first** runs — 0 and 3, not the primes.

- **twin-gap(L)** = the mean, over the two replicate pairs (0/0′ and 3/3′), of |cross(run) − cross(run′)|, in iterations.
- **between-gap(L)** = the mean, over all 15 pairs of the six individuals (every unordered pair of the canonical runs), of |cross(i) − cross(j)|, in iterations.

The canonical-run choice is part of the statistic, fixed now: seeds 0 and 3 each have two runs, and only the first (0 and 3) counts as the individual; the primes are replicates and belong to twin-gap alone. Counting a prime as an individual would double seeds 0 and 3 in the between-side of the comparison. Runs 0 and 3 therefore appear in both statistics — that is the registered statistic, not an oversight: the same eight runs feed both sides, and the test asks which kind of difference — twin or between — is larger on them.

**Resolved (raised by Ark, 2026-09-17; adopted from CC's review, 2026-09-17): the comparator's sample sizes are unequal — 2 twin pairs against 15 between pairs — and the deterministic mean-vs-mean comparison of §4's criterion carries no null model.** A permutation null over which runs are declared twins is not available: the twins are real replicate pairs, not a label that could have fallen on any other two runs. Registered instead, in review and before any reading: the **exact rank statistic** — the positions of the **2** twin differences among the **15** between-individual differences. With 2 against 15 the smallest attainable one-sided p-value is 1/C(17,2) = 1/136 ≈ 0.0074, so the test is feasible and not degenerate. This is a **registered, printed statistic** (§10), computed and reported at every accepted level alongside twin-gap(L) and between-gap(L); it does **not** replace the criterion sentence below, which remains the deterministic ACCEPT/fail rule — the rank statistic is reported beside it, not instead of it.

**Exclusion rule.** A level at which **any of the eight runs never crosses** (no checkpoint with curve value ≤ L) is excluded from the grid; the exclusion count is reported with the result. After this exclusion both statistics of §4 are computable at every remaining level by construction — the eight runs include both twins and all six canonical runs.

**The criterion, in one sentence, fixed before reading:**

> **ACCEPT only if between-gap(L) > twin-gap(L) for every accepted level L; any other outcome is a fail.**

An **accepted level** is a grid level that survives both the exclusion rule above and the disqualification rule of §5. If no accepted level remains, there is nothing to accept and the outcome is governed by §5's whole-test rule, not by this sentence.

## 5. Resolution and disqualification (plan §4(c), (d))

**The instrument's resolution, stated rather than assumed.** The checkpoint grid is **not uniform**: iterations 0, 12, then steps of 3,600, with a final step of 1,596 to 250,008 — 72 points [PUBLISHED: plan §4(c), `results/night4/night_report_checkpoints.csv`]. Crossing times are quantised by this grid: they can only take checkpoint iterations as values. Consequently the *differences* of crossing times are themselves quantised — multiples of the 3,600 step, except where a difference crosses the first pair of checkpoints (0 and 12) or the final step (1,596); all three numbers are the grid's own, published with it. "Comparable to one step" is therefore not a fuzzy phrase but the grid's own granularity.

**Disqualification rule — symmetric, fixed after review (CC's review, 2026-09-17, adopted).** A level is **UNREADABLE** if **either** twin-gap(L) **or** between-gap(L) is ≤ **3,600 iterations**, one checkpoint step — "less than or comparable to one step". The rule as first registered dropped a level only when twin-gap(L) sat at or below one step, while a level whose between-gap(L) sat at or below one step was left to fail the criterion of §4 instead of being dropped — the same resolution limit treated as "unreadable" on one side of the comparison and as a substantive result on the other, which biases the whole test toward failing. Symmetric UNREADABLE removes that bias: on a grid with 3,600-iteration spacing, either gap at or below one step means a pair (twin or between) crosses at the same or an adjacent checkpoint, and the test would then be measuring the checkpoint interval, not the individuals, regardless of which side of the comparison it sits on. Such a level is **dropped, not scored as weak or as failing**, and the drop is reported together with which side (twin, between, or both) triggered it. This clause is written before the computation because recording it afterwards turns it into an explanation — the precedent is on record: replicate 0′ came in at 1.1104 % against a 1 % tolerance, and the discussion of the instrument's floor started after (plan §4(d), `docs/experiments/001-run0-and-replicate.md:68`).

**Whole-test rule.** If more than half of the grid as constructed in §3 leaves the test — dropped as unreadable here or excluded under §4, together — then the grid has evaporated rather than thinned, and the **whole test is unreadable**: reported as unreadable, not as a fail and not as a pass. (Registered choice — fix in review: the denominator is the grid as constructed at §3 step 3, before any exclusion.)

**The denominator, in words rather than by the order of lines in the script.** The denominator is the **tested set** — the grid of §3 after the withdrawal of §11, i.e. **23 levels**. The withdrawn levels enter neither the numerator nor the denominator, because they are never tested at all. This is the **strict** reading of the two available: a smaller denominator lowers the bar, so it brings `TEST UNREADABLE` closer and cannot be accused of manufacturing a pass. It is written here so that it is not argued about after the reading, when any choice would look like fitting.

**The whole-test threshold in absolute numbers, and a correction to the figure raised in review (Ark asked for the absolute form; the number is not his).** The rule fires when more than half the tested grid leaves. On v1's 34 levels that was 18; Ark computed **13 of 25** for v2's grid. It is **12 of 23**: the two levels withdrawn by the §11 caveat are never tested at all, so counting them in the denominator would make the rule laxer than it reads, and the registered denominator is the **tested set** — 23 levels — with the rule firing at **12**. The script prints the threshold alongside the count for exactly this reason: the same proportion on a smaller grid is a different number, and a proportion read as "someday" is read as "right here" once it is a number.

**The anchor fix is not neutral to the regime report, and that is a consequence rather than a side effect (Ark, 2026-09-17).** v2 moves the whole band: v1 spanned 1146.0—1212.0, v2 spans 1162.0—1210.0 less the two withdrawn levels. A level higher in loss is crossed earlier, a lower one later, so **which** accepted levels straddle the 150,000 boundary is a property of the v2 grid. The straddle report is therefore read for v2 and **must not be compared with any figure computed for v1's band**. Neither of us checked in advance how the composition changes: the curve value at the checkpoint after 150,000 would answer it, and that is a reading, not a structural quantity — so this says the composition changes, not by how much.

**The selection this rule creates, named before the reading (Ark, 2026-09-17).** Symmetry fixed one bias and exposed another, which is not removed and is therefore stated instead. `twin-gap(L)` is the **mean over two pairs**, so dropping at ≤ 3,600 means a level survives only if at least one twin pair crosses **two or more checkpoints apart** (a sum ≥ 7,200). But twins are expected to agree — so the rule discards exactly those levels where the endpoint looks best and keeps those where the twins happened to diverge most. The direction is toward failing. Two consequences follow and both are registered here rather than discovered afterwards:

1. an `ACCEPT` obtained under this rule is obtained on the **unfavourable subset** of the grid, which makes it stronger than it looks, not weaker;
2. a `TEST UNREADABLE` verdict from the whole-test rule is a statement about **the grid's granularity and this selection** — not about the individuals, and not evidence that the endpoint class fails. If it fires, it is reported in those words.

## 6. Positive control (plan §4(e))

The criterion in §4 only tests discrimination, and a statistic that discriminates nothing passes it the same way (plan §4(e)). The control: the endpoint must separate trained from untrained. Two prongs, both fixed now:

- **Finiteness — a completeness check, not a control (demoted in v2).** For every run, every grid level strictly between that run's iteration-250,008 curve value and L0 must be crossed at a finite iteration. **This cannot fail, and calling it a positive control overstated the instrument:** by §2's definition a crossing is the first checkpoint at or below L, and for any level above a run's final value that run's own final checkpoint is itself at or below L — so a crossing always exists. The only way it can come out false is a missing checkpoint, which the layout guard already catches with its own exit code before the control runs. It is kept, printed, and named for what it is: a redundant completeness assertion. Found by Ark, 2026-09-17.
- **The untrained state sits above every accepted level — an invariant that cannot fail on this substrate (v4).** *If any accepted level is not below all iteration-0/12 curve values of all runs, the instrument fails its positive control and the test is void* — whatever the criterion of §4 would have said. A level at or above a run's untrained value is crossed before training begins and separates nothing. **Read the italics as a formal invariant, not as a gate this substrate can trip.** Under the v3 anchors this prong is empty at any data and its exit-4 branch is unreachable, for the reason given three paragraphs below. It is kept in the live form because it governs any substrate where the anchors are decoupled; on *this* substrate the registration has **no positive control that can fail**, and §4's criterion is read without one. A reader who takes this bullet as a passed gate has been misled by it — which is why the correction sits in the bullet and not only in the prose.

The published anchors, for scale [PUBLISHED: plan §4(e), `results/night4/night_report_checkpoints.csv`, iterations 0 and 250,008]: the untrained level **1212.5556**, and the learned gain within the same field **63.7481** for seed 0 — five times the largest twin gap in the curve field, **12.1749**. If the endpoint cannot see a difference of that size it is dead regardless of what it says about twins. This is the control the retired L3 probe failed: four cells agreed neatly while the instrument could not pass its own positive control (plan §4(e)).

**The control of this registration is executed by construction, and that is a property to state rather than a strength to claim (Ark, 2026-09-17, on his own v2 fix).** The second prong tests that every accepted level sits below every untrained reading. But the v3 upper anchor **is** that minimum — `L0` and the prong's `min_side` are computed from the same set (the eight runs × iterations {0, 12}), and the grid lies strictly below `L0` — so the prong is empty **at any data**, and its failure branch (exit 4) is unreachable. Demanding that both guards be empty by construction, as v2 did, makes them clean and thereby **dead**: a guard that cannot fail cannot distinguish a working instrument from a broken one.

So, precisely: the substance of the control survives but has **moved into the grid rule** — a level at an untrained reading would be crossed at iteration 0 and separate nothing, and `L0` excludes such levels **by rule instead of by test**. Both prongs are therefore completeness checks: their failure would mean a defect of layout or a substituted input, not a weak instrument. **The one checkable claim the instrument still makes is the scale** — 63.7481 against 12.1749 — and it is **printed, not gated**. The exit-4 branch is retained and marked: unreachable while the anchors are coupled as in v3, kept as insurance for a substrate where they are not.

The control is applied before the criterion (§3 step 5): a control failure voids the test, and the criterion is then not read. On this substrate that ordering is a formality — neither prong can fail here — so the sentence registers a precedence for a future substrate and **must not be cited as evidence that this reading was gated**. What the reader is owed, plainly (v4): **this registration enters its one reading with its positive control satisfied by construction, which is to say with none.** The scale figures in the paragraph above — 63.7481 against 12.1749 — are printed for the reader's judgement and gate nothing. The honest form of the residual risk: if the substrate were silently substituted for another, this test would not notice through its control, only through the sha256 of §10.

## 7. The field, named — and the numbers that are not its own (plan §4(f), as amended)

The test runs on the **checkpoint curve**, a different field from the 250,000 hook, and its twin gaps are its own [PUBLISHED: plan §4(f), recomputed by CC 2026-09-17 UTC, amended by `4574e13` after Ark's review]: at iteration 250,008 the curve gives **0′ − 0 = 12.1749** and **3′ − 3 = 7.6059**. The trained spread in this field is **18.7403 over all eight runs** and **12.1922 over the six individuals** — both are named because they are different quantities and the eight-run figure mixes replicates into the population it is spread over (the plan's §2/§4(f) defect, fixed in `4574e13`); on the six-individual figure the largest twin gap is nearly the whole spread, which is the situation this test exists to measure, not a reason to expect it to pass.

**Forbidden numbers.** The hook-field values — **12.7279**, **10.4309**, **5.1425**, and the hook range **17.5803** — must not enter any computation of this test: not as thresholds, not as tolerances, not as expected gaps. Every comparison in the criterion is computed in the field the test uses; carrying the hook's numbers into a curve-based computation is the population error of plan §1, one level down (plan §4(f)).

The error in its original form, for the record: a three-seed figure and a six-individual figure at the same rung were confused once already, and the smaller of the two was carried into a cost estimate (plan §1). The rule above exists so that the same confusion between two fields at the same iteration cannot happen a second time through this test.

## 8. Inherited fragility, and the second free branch (plan §4(g))

The aggregate under every curve here is the same **16 items over 6 held-out scenes, two of which flip the seed order** [PUBLISHED: plan §2, `results/night2/diagnostics/dropk/dropk_summary.md`: `sequence_02_ambush_2` and `sequence_09_bandage_1` flip; `bamboo_1` and `cave_4` do not]. Crossing time is computed from that aggregate and inherits this fragility. This is **not a blocker**; it is recorded so that a fail of this test carries its correct size — a fail of the endpoint on this aggregate, not a proof that no reachability endpoint exists.

**The second free branch.** If the test fails, the next step is not a GPU run: recompute the aggregate under alternative item weightings from the per-item tables already on disk — `results/night2/diagnostics/per_item_250008.csv` — no GPU, under **its own future registration**. That branch is registered here only as a next step after a fail; it is not licensed by a pass, and nothing in this document permits reading it before this test's verdict is recorded.

## 9. What this test does NOT establish

- **A fail produced by a tie is a statement about the grid's grain.** The criterion of §4 treats any outcome other than `between-gap(L) > twin-gap(L)` as a fail, ties included. Crossing times are quantised to 3,600 iterations in the interior of a run and to 12 and 1,596 at its ends, and both gaps are means of such quantities, so exact ties are not unlikely. A verdict that turns on one tie says the grid is too coarse to separate the two sides at that level; it does not say the twins and the individuals differ by nothing (Ark, 2026-09-17).
- **It is not the (b) test** of `docs/preregistration-cheap-vs-expensive.md`. (b) is read once, at the final N, when all individuals are in (plan §6); this test touches no ρ, no rung, no ranking of that registration.
- **It licenses no N.** N (8 or 10) is chosen after the plan's step 3 (plan §3 item 4, §7 item 2); nothing here estimates, bounds or prices a population size.
- **A pass establishes one thing only:** that on this substrate, at the eight runs on disk, the crossing-time endpoint separates twins from individuals (plan §3 item 3 — "the endpoint is readable at N = 8 and road C is not needed to rescue it"). It is not a validation of any surrogate, any early cut-off or any kill-switch; those claims, if any, belong to the other registration and are not advanced a single step by this test.
- **It is not a decision between roads A and C.** The verdict feeds the plan's §3 item 3 gate; the gate's wording and the roads are the plan's and Mike's. Road C — changing the population — is covered by no document (plan §7 item 6).
- **Nights figures remain uncitable.** "~53 nights", "~16 nights" and "~5 nights" are products of a signal/noise model the data contradict (plan §2); N is currently not estimable, and no outcome of this test re-estimates it.

## 10. Substrate and boundaries

- **Data substrate:** **`results/night4/night_report_checkpoints.csv`** — 72 aggregate `val_loss` checkpoints × 8 runs in one file; the script's resolver is general over the night files as an implementation detail, but the registered substrate is this path; two replicate pairs (0/0′ and 3/3′); individuals seeds 0–5 with canonical runs 0, 1, 2, 3, 4, 5. ## 11. What would invalidate this registration

The registration is void, and is reported as void, if any of the following happens after a result is seen — and the reading is void if any happens before it:

- The grid constants (Lmin, the grid list) are computed, inspected or adjusted **after any crossing time has been computed**, or in any order other than §3's steps 1–5.
- Interpolation between checkpoints is used anywhere, under any name.
- Any hook-field number (12.7279, 10.4309, 5.1425, 17.5803) is substituted into any computation of this test.
- Any threshold is added or removed after the reading, beyond the exclusion rule (§4) and the disqualification rule (§5) as written here.
- Any `cross(r, L)` is computed — by anyone, for this test or "just to look" — before this document is reviewed by Ark and CC_windows.
- The reading is produced by an uncommitted script, by a script written after the data was looked at, or by hand (§10).
- The reading is done a second time under changed constants, or the acceptance statistic, the canonical-run choice, or the disqualification cut is altered after the data is touched.
