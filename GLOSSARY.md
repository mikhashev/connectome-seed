# Glossary

**Written:** 2026-09-23 07:50 UTC (14:50 local, +07:00), by CC (subagent), on Mike's word
(owner, DPC Research group, 2026-09-23 07:04 UTC: "create GLOSSARY.md here with proper English
terms, so none of you invent words", translated from Russian). The terms reviewers asked for come
from Ark, Johnny and Zcode (DPC Research group, 2026-09-23 07:26–07:38 UTC).

**One term per concept, one meaning per term.** Each row gives the term this repository uses, what
it means, what it must not be confused with, and the file that defines it or first uses it. The
**Meaning** column paraphrases that file; the **Source** column is the file, and the file wins
whenever the two disagree. Where the repository used two words for one thing, one is chosen and
the other is listed as a **deprecated synonym**. Where one word was used for two things, the word
is split and each sense is named. A row whose concept has no home in the repository says **no
defining source yet** instead of inventing one.

**Rules of use.**

- Take the term from this file before writing a record. A new term is added here, with its source,
  **before** it is used in a record (`docs/CHECKLIST-research-repo.md` § Language).
- A deprecated synonym is not used in new text. It stays where it already is: registered and
  hash-locked files are never edited for vocabulary.
- **This file carries no result value.** It holds definitions, registered constants and structural
  counts of the bank only. It was written without opening
  `docs/plans/2026-09-23-first-rule-proposal.md` or anything under `results/genome/c6/rules/`, and it
  defines no term internal to the first rule, so reviewers who must stay blind to that rule can
  read it.

The format follows `docs/GLOSSARY.md` of the dpc-messenger repository: one table row per term,
the term in bold in the first column, sources as relative links. Its checker,
`tools/backlog/glossary_check.py` there, verifies that every source link lands on a file.

## 2. The object: the bank and its parts

| Term | Meaning | Not to be confused with | Source |
|---|---|---|---|
| **bank** | The object a rule has to regenerate: the fly's type-pair wiring compiled by flyvis. It has 65 cell types, 604 compiled type pairs and 2,355 offset rows `(source, target, du, dv) → n_syn`, one sign per pair, identical at extent 15 and extent 5. **Real bank** means this one. Synthetic variants are called banks too: shuffled bank, planted bank. Deprecated synonyms: "compiled rule bank" (a quotation in the C6 spec §0), "shuffled table" and "planted table" (first-rule search criterion). | **type-pair table** (the 65 × 65 layout the bank is scored on); **matrix** (a numeric 65 × 65 array derived from the bank); the **json** (605 entries before compilation). | [bank README](results/genome/bank/README.md) lines 9–12, 46–55; [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) §2 |
| **generation-zero bank** | The bank as extracted from flyvis 1.2.0, with its birth ids: the root of the evolutionary tree. | a later genome's decoded bank. | [bank README](results/genome/bank/README.md) title; [REGISTRY.md](results/genome/bank/REGISTRY.md) rule 6 |
| **json entry** | One edge entry of the connectome json: 605 of them. One, `Lawf1 → Lawf1`, never compiles, which leaves 604 **compiled pairs**. | **cell type** (**type**) | One of the 65 neuron types of the flyvis connectome, given to a rule as an opaque index 0–64 in birth-id order. | **node** (one neuron instance of a type); **cell** (a cell of the type-pair table). | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) A1; [types.csv](results/genome/bank/types.csv) |
| **node** | One neuron of the compiled flyvis network. There are 45,669 at extent 15 and 5,759 at extent 5; the count is a lattice parameter, not a biological count. | **type pair** | An **ordered** pair `(source type, target type)`. | **type-pair table** (**table**) | The 65 × 65 grid of ordered type pairs, 4,225 **cells**, each carrying the four fields. | **cell** | One cell of the type-pair table, meaning one ordered type pair, empty or not. **Non-empty cell** = one of the 604 compiled pairs. **Empty cell** = one of the other 3,621, including `Lawf1 → Lawf1`. | **node** (a neuron); **cell type**. | **matrix** | A numeric 65 × 65 array computed from the bank for measurement: **L** = ln(1 + total synapses per pair); `C` connection (0/1); `S` sign; `Q` log-count bins; `K`; `N32` raw float counts. | **table** (the scored layout); **L1–L4** (offset-pattern levels); the cell types **L1–L5**. | [REGULARITY-READING.md](results/genome/bank/REGULARITY-READING.md) §2, §4; [acceptance, part 2](docs/plans/2026-09-23-c6-amendment-acceptance-2.md) §3 |
| **offset** / **offset row** (**row**) | An **offset** `(du, dv)` is a displacement on the hex lattice from a source column to a target column. An **offset row** is one `(source, target, du, dv)` row with its `n_syn`. An offset has no birth id of its own: it is addressed as (pair birth id, du, dv). | **offset set** (all offsets of one pair). | [REGISTRY.md](results/genome/bank/REGISTRY.md) § "Offsets do not get ids of their own"; [offsets.csv](results/genome/bank/offsets.csv) |
| **row strata: `in_json` / `hull_filled` / `dropped`** | `in_json`: the 2,117 compiled rows matched to the json, **scored**. `hull_filled`: the 238 rows produced by the convex-hull fill with `n_syn = 1`, reported and **not scored**. `dropped`: the 23 json rows that never compile, not targets. | — | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) §2 "Strata"; [bank README](results/genome/bank/README.md) lines 20, 46–55 |
| **fields: existence, offset set, counts, sign** | The four things a predictor must produce per cell. **Existence**: whether the pair is one of the 604. **Offset set**: the pair's `in_json` offsets. **Counts**: `log1p(n_syn)` per `in_json` row. **Sign**: the pair's `alpha`, ±1. | **exact offset set** (225) | An offset set compared exactly, with no symmetry applied. The compiled bank has 225 distinct exact sets. **This is what C6 scores** (A21). The regularity reading calls it level **L1**. | **canonical shape** (144); **offset set with counts** (327). | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) A21; [REGULARITY-READING.md](results/genome/bank/REGULARITY-READING.md) §3 |
| **canonical shape** (144) | An offset set reduced to canonical form under the **12 symmetries of the hex lattice** (6 rotations × reflection): the lexicographically smallest of the 12 images. "D6 canonicalisation" is a reviewer's name for the same thing; the repository's words are "up to the 12 symmetries of the hex lattice". | **exact offset set** (C6's object); **profile shape** (§9). | [REGULARITY-DECLARATION.md](results/genome/bank/REGULARITY-DECLARATION.md) §"The measures" (b); [C6 README](results/genome/c6/README.md) |
| **offset set with counts** (327) | Level **L2**: the exact set with each offset's `n_syn` divided by the pair's total, rounded to 2 decimals. The bank has 327 distinct such patterns. **L4** is L2 up to the 12 symmetries. | the C6 **counts** field (per-row `log1p(n_syn)`, not normalised). | [REGULARITY-DECLARATION.md](results/genome/bank/REGULARITY-DECLARATION.md) §"The measures" (b); [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) A21 |
| **offset-pattern levels L1–L4** | The four levels of the regularity reading's offset patterns: L1 exact, L2 exact with normalised counts, L3 shape, L4 shape with normalised counts. Always write "level L1", never a bare "L1". | the cell types **L1–L5**; the matrix **L**; **level** of a profile (§9). | [REGULARITY-DECLARATION.md](results/genome/bank/REGULARITY-DECLARATION.md) §"The measures" (b) |
| **`pattern`** | Split. (1) **`pattern` (flyvis node field)**: the node production kind and stride, `stride [1, 1]` for 63 types and `[3, 2]` for Lawf1 and Lawf2. It is an admissible per-type input. (2) **offset pattern**: a pair's set of offsets (the regularity reading's word). For sense 2, write "offset set". | "connection pattern" in REGULARITY-READING §2 means which pairs connect (existence). | [bank README](results/genome/bank/README.md) line 44; [REGULARITY-READING.md](results/genome/bank/REGULARITY-READING.md) §2–§3 |
| **hex lattice** (**lattice**) | The hexagonal grid of columns on which flyvis tiles every type, with axial coordinates `(u, v)`. Offsets live on it. **Extent** is the radius of the hex disc (15 or 5). "Lattice" means this grid and nothing else. | "lattice parameter" (VISION: the node count, set by extent); the **quantisation grid** of a float type (the checklist's "Lattice 2⁻¹⁶", R2), which should be called a quantisation step. | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) §4.1, A21; [VISION.md](VISION.md) lines 187–192; [CHECKLIST](docs/CHECKLIST-research-repo.md) item 9 |

## 3. Identity and heredity

| Term | Meaning | Not to be confused with | Source |
|---|---|---|---|

## 4. Predictors, description length and opponents

| Term | Meaning | Not to be confused with | Source |
|---|---|---|---|
| **predictor** | Anything that outputs the four fields for a list of cells: the rule under test, every null and opponent, the oracle, the stored bank. Every predictor is scored as a pair (**program**, **data**). | — | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) A5 |
| **rule** (**candidate rule**) | Split. (1) **candidate rule**: in genome and C6 records, a predictor submitted to C6 that claims to regenerate the bank from a smaller object. "The rule" means this sense. (2) **reading rule**: a decision procedure registered before a reading, such as a pass rule or Ark's DRIFT/SMOOTH/AMBIGUOUS rule. Write "reading rule" for sense 2. (3) The **birth-id rule** is always named in full. | **grammar** (VISION's generative object); **criterion** (one registered condition). | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) §0, §1; [CHECKLIST](docs/CHECKLIST-research-repo.md) items 6, 16 |
| **program** / **data** / **learner** | **Program**: the predictor's decode module source, charged by its lzma size. **Data**: a dictionary of named numpy arrays, charged per item. **Learner**: the code that produces the data from training cells; it is **not charged**. | the **fit** (one call of the learner). | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) A5 |
| **decoder** | Split. (1) **decode program**: a predictor's charged decode module (`results/genome/c6/decoders/*.py`). (2) **uncharged decoder**: CPython 3.10, its standard library, numpy and the harness's scoring code, the same for every predictor. The original §4.2 said "the fixed decoder … is not charged"; A5 replaces this. (3) **flyvis as decoder**: flyvis compiling a json to a bank, which is the second of the two readings. (4) flyvis's task **decoder** network, trained with each individual (measurement line). | — | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) §4.2, A5; [REGISTRY.md](results/genome/bank/REGISTRY.md) § "The two readings"; [pre-registration](docs/preregistration-cheap-vs-expensive.md) §2 |
| **DL** (**description length**) | The bits a predictor is charged: the program's lzma size × 8, plus its data under A5's bit table (32 per real, Elias-gamma per integer, ⌈log₂ m⌉ per symbol). The number of starts is **not** charged. | compressed sizes in the regularity reading (zlib or lzma bytes of a matrix), which are "not estimates of description length". | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) A5; [REGULARITY-READING.md](results/genome/bank/REGULARITY-READING.md) § "What the numbers do not say" |
| **DL(bank)** / **S_all** | The bank's own length: predictor S_all, a decode module that reads stored cells, plus all 604 non-empty cells in the stored-cell format. Hull rows are not stored. | — | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) A5 |
| **one-tenth limit** | P2's length half: DL(rule) ≤ DL(bank) / 10. It is unchanged by every amendment. Deprecated synonyms: "size limit", "length limit". | **M18** (a reference mark on the size axis, not a limit). | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) §5.1 P2, A15 |
| **M18** | The 18-component mark: 18 × (65 + 65) × 32 = 74,880 bits, the parameter cost of a rank-18 factorisation of the log-count table. A rule below M18 must still beat D_k\*. | **k90** (the count 18 it is built from); **k18**. | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) A6 |
| **genome** | In C6 records, the object a rule stores, which is small enough to be called a genome: "a rule small enough to be called a genome regenerates the bank, and the regeneration is not a copy of the table". For the planted rule, its genome is its class vector. | **grammar**; **seed** (§9); VISION: "the connectome is the product of development; the genome is the process". | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) §0; [acceptance](docs/plans/2026-09-23-c6-amendment-acceptance.md) § "The planted rule (PR)" |
| **grammar** | Point 1 of `idea.md`: a rule that *produces* the wiring table (which types exist, which pairs connect, at which offsets, with which signs). | **null** | A predictor built from type marginals only, fitted on training folds: **N0**, **N1**, **N_EB**. | **opponent** | Any predictor a rule must beat under P1–P4: the nulls, D_k^N1 at k\*, D_k^N0 at k\*_armed, BF_r, RP_r. **Trained opponent** = BF_r, which gets the rule's number of starts. | **control** (a run of the exam on a known input, §8). | [C6 spec](docs/plans/2026-09-23-c6-control-specification.md) A17–A19; [acceptance, part 3](docs/plans/2026-09-23-c6-amendment-acceptance-3.md) (a) |

| **armed D_k** (**D_k^N0**; code key `dk_armed`) | N0 plus the first k stored cells, with no N1 inside it ("one basis, one charge"). P2 compares the rule with it at **k = k\*_armed**. ## 5. Folds, fits, starts and runs

| Term | Meaning | Not to be confused with | Source |
